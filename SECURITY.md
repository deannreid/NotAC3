# Security Policy

## Supported versions

Not A C3 is under active development. Security fixes are made against the
current 4.0 release line.

| Version | Supported |
|---|---|
| 4.x | Yes |
| Earlier versions | No |

Please confirm the issue still affects the latest available release before
submitting a report.

## Reporting a vulnerability

Do not report security vulnerabilities through a public GitHub issue.

Use GitHub's private vulnerability reporting form:

[Report a vulnerability privately](https://github.com/deannreid/NotAC3/security/advisories/new)

Include the following where possible:

- The affected version and component
- A clear description of the vulnerability and its impact
- The minimum steps needed to reproduce it
- A safe proof of concept, if one is required to demonstrate the issue
- Any suggested fix or mitigation

Do not include real credentials, private keys, tokens, target information,
collected data, or live infrastructure details. Replace sensitive values with
safe examples.

You should receive an acknowledgement within five working days. Updates will
be provided through the private advisory while the report is investigated.
Please allow time for a fix and coordinated disclosure before publishing
technical details elsewhere.

## Scope

Security reports should relate to Not A C3 code, packaging, authentication,
authorisation, data handling, agent communications, or supported deployment
behaviour.

General bugs and feature requests should use the normal GitHub issue forms.

## Research expectations

Only test systems you own or have explicit written permission to assess. Do
not access other people's data, disrupt services, maintain persistence, or go
beyond the minimum work needed to confirm a vulnerability.

Good-faith reports that follow this policy are appreciated. This policy does
not authorise testing of third-party services or infrastructure.
